# 개발 일지 기록 (Notion)

현재 세션에서 진행된 내역과 코드 수정 사항을 Notion의 ClassicHub **개발 일지** 데이터베이스에
하나의 페이지로 기록한다. 기록은 반드시 **시간(커밋) 순서**로, **맥락을 포함해서**,
**섹션을 나눠 가독성 있게** 작성한다.

## 1. 대상 데이터베이스

- 데이터베이스: 📒 개발 일지 — https://www.notion.so/fb03fa78a6b3409a905f96e315661f80
- 데이터 소스: `collection://591277e0-9f76-4784-b166-5a8d9bb8fc1c`
- 위치 경로: Dev / Projects / ClassicHub

**존재 확인이 최우선이다.** 기록을 시작하기 전 `fetch`로 위 데이터베이스 URL을 조회한다.
조회에 실패하거나 데이터베이스가 존재하지 않으면 **작업을 중단하고 사용자에게 다시 질문한다**
(이동했거나 이름이 바뀌었을 수 있다). 임의로 새 데이터베이스/페이지를 다른 곳에 만들지 않는다.

### 속성 (properties)

| 속성 | 타입 | 내용 |
| --- | --- | --- |
| `제목` | title | 세션 전체의 핵심 성과를 압축한 제목 |
| `날짜` | date | `date:날짜:start` = 작업일 (`YYYY-MM-DD`) |
| `요약` | text | 맥락·원인·**커밋 해시**를 포함한 밀도 높은 단락 요약 |
| `관련 PR` | url | 세션 작업과 직결된 PR URL (없으면 생략) |

## 2. 작성 절차

1. **세션 내역 수집**
   - `git log --oneline` 등으로 이번 세션의 커밋 목록을 확인하고 **커밋 순서(오래된 것부터)** 대로 정렬한다.
   - 커밋으로 남지 않은 작업(논의, 조사, 롤백, stash 보관 등)도 세션의 일부이므로 빠뜨리지 않고
     별도 섹션("세션 내 기타 작업")으로 기록한다.
   - 각 작업마다 **맥락(왜 했는가)**을 확보한다: 재현된 증상, 사용자의 요청 배경,
     검토한 대안과 트레이드오프, 기각된 제안. 맥락 없는 변경 목록은 일지가 아니다.
2. **기존 항목 형식 참조** — 최신 항목 1개를 `fetch`해 어조와 구조의 일관성을 유지한다.
3. **페이지 생성** — `create-pages`의 parent를 위 데이터 소스 URL로 지정한다. 본문은 아래 템플릿을 따른다.
4. 생성된 페이지 URL을 사용자에게 보고한다.

## 3. 본문 템플릿 (시간 순서 + 섹션화)

```markdown
# 개요
<무엇을, 왜 했는지 — 증상/요청 배경/목표. 이 세션의 출발점이 되는 맥락>

# 1. <첫 번째 작업 소제목>
## 배경
<이 작업을 하게 된 맥락: 버그 원인, 요청 사항, 설계 논의에서 나온 결론과 이유>
## 커밋 `<해시>` — <커밋 제목>
- 변경 파일과 핵심 내용 (불릿)
- 필요하다면 핵심 코드 스니펫 (아래 규칙 준수)

# 2. <두 번째 작업 소제목>
(이하 커밋 수만큼 반복 — 반드시 커밋 순서대로)

# N. 검증 결과
- 테스트 통과 개수, tsc/빌드 결과, 실측 검증 내용

# N+1. 세션 내 기타 작업 (커밋 없음)
- 논의·조사·롤백·stash 등 커밋으로 남지 않은 내역

## 4. 작성 규칙

- **시간 순서(커밋 순서) 준수**: 섹션 번호는 커밋 순서를 따른다. 나중에 한 작업이 앞에 오면 안 된다.
- **섹션/소제목 필수**: `#`로 큰 단계를, `##`로 작업/커밋 단위를 나눠 가독성을 확보한다.
- **git 해시 연결**: 각 작업의 소제목에 해당 커밋 해시를 명시한다.
  예) `## 커밋 \`a1b2c3d\` — Slack 요약에 삭제 상태 추가`
  해시가 없는 작업은 "(커밋 없음)" 또는 "(롤백됨)"을 명시한다.
- **코드는 요약만**: 전체 diff를 붙이지 않는다. 핵심 변경만 **5~15줄 내외의 스니펫**으로 제시하고,
  스니펫이 해당 커밋의 것임이 드러나게 소제목 아래에 배치한다.
- **맥락 필수**: "무엇을 바꿨는가"보다 "왜 바꿨는가(증상 → 원인 → 선택 이유 → 결과)"가 먼저 온다.
- **롤백된 작업도 기록한다**: 구현했다가 되돌린 작업은 "롤백됨"과 이유를 남겨 의사결정 이력을 보존한다.
- 요약(`요약` 속성)에는 커밋 해시를 괄호로 병기해 본문 대조가 가능하게 한다.
